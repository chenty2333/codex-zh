# 实现与一致性约束

```text
原生 codex TUI
   │ 鉴权的 loopback WebSocket / JSON-RPC
   ▼
codex-zh Bridge
   ├── 用户 text：完整原文 → DeepSeek Responses → 英文正文
   ├── 正文与 plan：完整源条目 → DeepSeek Responses → 中文正文
   ├── 当前回合临时文字：按预算接纳任务，回合结束释放，不写盘
   └── 工具、审批、附件、控制事件：原样转发
   │ JSON-lines stdin/stdout
   ▼
原生 codex app-server → 原生模型、工具和工作目录
```

## 协议范围

输入仅变换 `turn/start` 和 `turn/steer` 中 `type=text` 的文本。其他输入内容与协议字段保持原样。译文不沿用原文的 UTF-8 字节位置，因此提交时将 `text_elements` 清空；当前输入回显仍使用原始文字和原始注解。图片、技能等非文字附件原样转发。

输出仅变换 `agentMessage` 和 `plan` 的实时 `item/started`、`item/*/delta`、`item/completed` 及当前回合最终快照。历史请求和响应完全透传，包括 `thread/resume`、`thread/read`、`thread/fork` 及所有历史分页。工具与服务器发起的请求正常情况下即时转发；输入和正文输出分别按 thread 排队。中断直接触发 AbortController，并继续向原生服务端转发。

应用层输入回显通过 `clientUserMessageId` 与内容摘要恢复原始文本。摘要兼容原生服务端补齐的 `text_elements=[]`、`placeholder=null`、图片 `detail=null` 字段。

## 完整原文与直接返回

1. 缓冲 Codex 源文字增量，等待 `item/completed` 的完整原文。
2. 将整条原文作为 Responses 请求的 `input` 字符串；翻译指令放在 `instructions` 中，指定目标语言、只输出对应译文、内容和格式对应、不添加说明。
3. 读取接口的最终正文。SSE 中的中间文字不显示，也不与最终正文做比较。翻译正文不经过 JSON 解析、内容校验或格式修复。
4. 直接将返回文字设为 `state.emitted` 并发送一个本地文字增量。`item/completed.text` 和当前回合的最终快照复用该字符串。
5. 回合结束后删除临时输入与回复，以后读取历史得到原生保存的文字。

每条非空文字只调用一次翻译接口；语言、代码、数字和格式都由 DeepSeek 从完整原文中理解和处理。

## 失败与取消

输入是整条提交事务：翻译请求或容量预留失败时，向 TUI 返回错误而不发送 `turn/start` / `turn/steer`。输入回显映射只保存在当前回合内存中。

输出请求失败、超时或取消时，本条回复显示完整原文。已经显示的其他回复保持不变。代理不会将 DeepSeek 的错误响应正文插入用户回复。

## 内存与请求容量

每次接纳待译输入或回复前，预留四倍单条原文上限的字符预算。完成后按仍需保留的实际文字大小记账，回合结束、取消订阅或关闭连接时释放。译文不按长度或膨胀比例拒收，因此已接纳请求可能使当前保留文字超过接纳预算；容量不足时拒收新输入，新增回复显示原文。没有得到回应的输入映射最多保留 60 秒；明确属于活动回合后随回合清理。

回复的原文增量积累超限时，先发出已暂存的原文前缀，再将该条目转为原文转发；后续最终条目由原生 TUI 处理。整个回合达到条目数或字符预算时，新增回复也使用原文。

翻译 API 保留请求超时、响应体大小上限，以及对 HTTP 和接口失败事件的处理。这些是传输和资源管理，不判断返回译文的内容或格式。

传输层限制同时等待 Bridge 处理的帧数为 128，待处理帧/待发送文字达到 8 MiB 时暂停读取上游 stdout。单个 JSON 帧原有的 128 MiB 上限保留；大历史响应仅临时解析并转发，不加入翻译缓存。队列在翻译完成或请求失败后继续推进。过载时可能延后读取后续控制事件。

字符预算不是 V8/Node、临时解析结构或原生 TUI 的总内存限制。

## 原生持久化

启动器沿用原生 `history.persistence` 和 `history.max_bytes` 配置，TUI 与原生 Codex 使用同一 `CODEX_HOME/history.jsonl`。上下方向键共享已提交的输入原文，包括翻译前的中文 prompt；重启或切换两个命令后仍可取回。用户显式设置 `history.persistence="none"` 时不新增输入历史。全局 Codex 配置不改动。

输入回溯文件与会话记录用途不同：会话 rollout 仍保存实际提交给 Codex 的英文用户消息与 Codex 原始输出，供原生 `resume` 使用。中文回复译文仍只保存在当前回合内存中。

## 恢复对话

代理允许原生 TUI 同时打开主会话连接和 `/resume` 历史选择器连接。每条连接使用独立的 stdio 后台与请求状态，后台继承同一个 `CODEX_HOME`，直接共享原生 Codex 的历史库。关闭选择器连接不会中断主会话。

启动器仅在内存中记录最近一次成功创建、恢复或分叉的非临时会话 ID 和工作目录，退出后输出 `codex-zh resume <会话ID>`。原生远程恢复会沿用已保存的会话目录，无需再传 `-C`；显式指定 `-C` 时仍由原生 Codex 处理目录覆盖。普通历史读取、后台通知和临时会话不会覆盖这条提示。删除或归档当前会话后，提示改为打开历史选择器。

每次启动都会创建新的本地代理。退出前原生 TUI 输出的临时 `ws://` 地址随代理关闭而失效；使用启动器最后输出的恢复命令即可。进入后通过 `/resume` 选择原生历史，也可以在命令行使用 `resume --all` 跨目录查找。

## 代码导航

| 文件 | 作用 |
| --- | --- |
| `bin/codex-zh.mjs` | 启动原生 TUI，镜像 app-server 所需配置参数，管理进程生命周期 |
| `src/server.mjs` | 鉴权 WebSocket、stdio 帧处理、进程清理与输出背压 |
| `src/bridge.mjs` | 白名单字段变换、请求关联、消息排序、中断和历史恢复 |
| `src/deepseek.mjs` | 简短翻译指令、完整原文请求、读取 Responses 返回正文 |
| `src/translator.mjs` | 无缓存的整条翻译调用、透传与取消 |
| `src/diagnostics.mjs` | 请求错误的固定分类提示 |
| `src/resume.mjs` | 当前会话元数据跟踪与退出恢复命令 |
| `src/config.mjs` | 环境配置与系统钥匙环读取 |

本实现面向当前 Codex v2 app-server 消息，不改写未知协议方法。新增原生消息类型需要先确认格式并补充对应验证后才能翻译；默认透传保留兼容性。
