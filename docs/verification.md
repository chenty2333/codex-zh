# 验证记录

验证环境：Linux，Node.js 24.15.0，Codex CLI 0.154.0，DeepSeek `deepseek-flash`，2026-09-10。

## 自动化测试

`npm test` 的 38 项检查覆盖：

- 限定输入/输出字段变换，附件、模型配置、工具、审批和未知消息透传。
- 输入失败不提交；中文输入回显；原生补齐默认字段后的内容匹配。
- 源增量与最终源文字不同时，以权威文本生成唯一译文。
- 当前显示增量、完成条目与完成回合使用一致译文，历史读取保留原文。
- 连续 1,000 轮后所有记录与队列清空；单个 1,000 条消息回合的保留条目数受限。
- 源文字超限、翻译膨胀、输入排队超限、取消订阅和关闭后的资源释放。
- 慢请求、中断和已提交前缀后的失败回退；未创建译文文件。
- UTF-8 拆包、CRLF SSE、截断、非成功终止事件、流式与最终响应不一致。
- 段落遗漏、错误 ID、额外字段、保护标记缺失/重复/修改与新 Markdown 注入。
- 代码、diff、JSON、引号字面量、引用范围、链接和编号列表的结构保护。
- 真实本地 WebSocket → 子进程 stdio 的往返，以及未鉴权连接的拒绝。
- 慢翻译期间 1,000 条额外回复的背压：待处理任务不超过 128，恢复后全部转发。

`npm run check` 进行 JavaScript 语法检查和源码凭据模式扫描；提交 Git 前还用系统钥匙环中的实际密钥在内存中核对暂存源码，不输出密钥。

## 原生程序验证

`npm run test:native` 启动真实 `codex app-server --stdio`，使用本地确定性 Responses 模型端点，验证中文输入被转换成英文进入模型、原生 v2 消息返回中文，以及增量与最终回复一致。然后关闭代理和后台，启动全新后台并 `thread/resume`：旧用户消息和回复均为原始英文、不触发翻译，再发送新消息则继续显示中文。还检查原生 rollout 文件没有测试中文输入或代理中文译文、回合完成后临时字符数为零。测试后归档此次创建的合成会话。

`npm run test:tui` 通过 Python 的 PTY 启动未修改的真实 Codex TUI 和真实 app-server。输入“请测试翻译桥接。”，本地模型收到英文，TUI 显示“桥接已就绪。”，未泄露模拟模型的英文正文；正常 `/quit` 返回状态 0。前后比较原生输入历史中的测试 prompt 数量，确认本次不会额外保存中文输入。这项测试的 Codex 模型和 DeepSeek 端点都是确定性本地模拟，不消耗真实 Codex 模型调用。

## 长对话内存检查

`npm run test:memory` 使用真实代理与翻译保护逻辑、本地确定性翻译器，连续处理 20,000 个不同的输入/回复回合。每轮检查临时字符数、条目数、输入映射、待处理请求、控制器与队列均清零。每 4,000 轮强制 GC 并记录 heapUsed/RSS；预热后的堆增长须小于 8 MiB。此次实测从 4,000 到 20,000 轮增长约 76 KiB，没有随历史累计的译文。具体样本见 `.test-state/memory/report.json`；这不测量原生 TUI 的历史内存。

## 真实 DeepSeek

`npm run test:live` 使用真实 `/responses` 与 `deepseek-flash`，验证五组合成文本：代码/引号字面量、否定与未授权限制、仅翻译而不执行文本中的指令、不确定性表述、Markdown 与链接。检查保护片段逐字保留、换行相同、关键否定与不确定性词语存在、增量与最终文字相同。

这些语义检查是样例验证，不是任意自然语言完全等义的证明。网络断开时输入会停止提交，输出会保留尚未翻译的原文。测试结果和合成文本记录留在 `.test-state/live/report.json`，不会被 Git 跟踪。

## 未覆盖的兼容性

没有穷举全部原生工具、插件、所有操作系统或未来 Codex 版本。原生 TUI 的菜单、推理摘要和工具日志仍可包含英文。退出即停止本地后台的行为与常驻远程服务器不同；本版不支持断开后继续执行。
